The Problem

Most agentic AI stops at a working demo.

The hard part is everything after it: execution governance, observability, and failure handling. A system that can generate a signal is not the same as a system that can be trusted with capital.

The layer that decides outcomes is not the model.

Production evidence collected in our research program indicates that agent behaviour is driven by interface and execution design, not by model reasoning quality alone. This is the Operating-Layer Dominance Hypothesis — the starting point for the architecture below.

Architecture

Layer 1

Discovery

Signal generation and candidate search, structured so the search objective does not converge on the same crowded alpha as every other discovery layer.

Layer 2

Reasoning

Specialist agents analyse markets independently and produce decisions with their supporting context and constraints.

Layer 3

Execution Control

An isolated Rust core validates every decision for risk and execution eligibility. Nothing reaches the market unvalidated. The kill-switch is deterministic.

The split is deliberate: a component that can influence a decision is not the component that authorises it.

What the architecture enforces

  • No unvalidated order. Every decision passes risk and eligibility validation in an isolated control core before it can reach the market.
  • Full decision lineage. Every decision — accepted or rejected — is recorded and replayable. Accepted and rejected paths are both first-class.
  • Bounded authority. Authority carries explicit scope, validity, and revocation semantics, and is revoked at the authorisation boundary before subsequent execution.
  • Reproducibility. A decision is reproducible only from a versioned execution context — software, policy, model, configuration, and dependency versions are part of the decision state, not documentation.
  • Failure containment. A failed transition must not expose a valid-looking partial state, and committed state must survive process, node, or service failure.

Custody and control

Non-custodial by design. The software is licensed and run by clients on their own broker accounts. Capital stays in the client's name, and the system never takes discretionary control.

This is an architectural constraint rather than a contractual promise: because the control core validates execution eligibility instead of holding keys or balances, the platform does not need custody to operate.

Research program

About the author

I am an AI systems architect working on deterministic control for autonomous and multi-agent systems — the layer that decides whether a machine's decision is allowed to reach production. I am the founder of ZVAKTHOR, an algorithmic execution platform for global financial markets where specialist agents analyse markets while an isolated core validates every decision before execution, non-custodially, on the client's own accounts.
